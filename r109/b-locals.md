**Accept** — fixed in `9cff0f3`, with one correction to the choice offered. Excluding locals the way parameters are excluded was not an option I had: a local is a local whether the scanner can see its function header or not, and the only way to tell the two apart is to know it is inside a function body — which is a brace match, not a pattern.

So function bodies are blanked before the scan, which is what the invariant actually is about: a local runs when its function runs. `val path = app.filesDir` inside `saveAppsLocked` is correct code, and reporting it would be reporting a rule the invariant does not have. An `init` block is not a function body and its values are eager by definition, so it stays in scope. The message the assertion prints is now accurate for everything the scan can still report.

One thing that fix got wrong and `d793285` corrects: an expression-bodied `fun` has no brace of its own, so the first `{` after the keyword belonged to the expression and the region between was being blanked — including `private val sp by lazy { … app … }` on line 199. The body is now found from the parameter list's closing bracket, so an `=` between that bracket and the `{` means there is no body to blank.
